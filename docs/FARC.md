# Fabmaster FARC and FAZ imports

FARC is a sectioned ASCII job archive, distinct from Fabmaster FATF A/J/S rows. A FAZ file wraps one FAR job and its libraries in a ZIP. The reader validates section revision 1, matching `:EOSECTION` boundaries and the final `EOARCHIVE` section; it accepts exactly one FAR member in a FAZ and applies the normal ZIP size, CRC and expansion limits. The legacy numeric EOARCHIVE marker is not independently verified as a checksum, and the import notice discloses this. No archive member is written to disk.

The imported board uses `PARTS` placements, `PACKAGE` pin names, `NETS` electrical membership and absolute `FABXYDATA` positions. Counts and identities must agree across these sections. The package record contains both a display name and a library filename; only the latter links to `PACKAGE`. `NCPINS` networks remain disconnected, and net zero is an unnamed disconnection. Placement angles are tenths of a degree; coordinates are mils converted to millimetres. `TPIN`, `BPIN` and `DPIN` mean top, bottom and through-board pins. A placement carrying opposite-side physical pins is shown on both sides, with a notice. Via records become generated one-pin components on their declared side. Sparse tester IDs are not pin identities: repeated/zero tester fields are valid, and via identity uses its source record index.

Straight `TRACK` paths in `FORMAT` are joined into closed loops for the board outline; open chains are omitted with a notice and never closed artificially. Pad sizes are estimated; routing, library drawings and tester setup are omitted with a notice. Unknown revisions, XY record layouts/types and outline primitives are refused. Token count, nesting, input bytes and result records are bounded. Section scanning is linear even when terminators are missing. The diagnostic hook records only whitelisted section counts, declared counts, unit/variant codes and redacted numeric/line shapes. Synthetic tests cover physical coordinates, sides, network membership, compressed wrappers and malformed input.

A private collection validation opened 69 FAZ paths containing 49 distinct jobs, 451,164 components and 911,179 pins. Independent ZIP extraction and a separate source-record traversal found no differences in counts, pin positions, identities, nets, sides or placement positions/angles. All observed job metadata declares MILS. A misleading `.fz` ZIP job is recognized by the bounded first local filename `iperror.asc`; the complete ZIP directory and one valid FAR remain mandatory. No private samples are distributed.
