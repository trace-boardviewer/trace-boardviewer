# Interface texts and catalogs

TRACE speaks eight languages: `hu`, `en`, `de`, `fr`, `it`, `sk`, `pl`, `uk`. Every text a person reads comes from the catalogs; contributors who translate read [CONTRIBUTING.md](../CONTRIBUTING.md). This page is for people who add or move texts in the code.

## Layout

```
electron/locales/<language>/<namespace>.json     one folder per language, the same files in every folder
```

A namespace is a feature area. A key is `<area>.<name>` (`notes.copyText`, `unit.pins`) and lives in exactly one namespace file per language, the same one in every language. Each area belongs to one namespace, so the namespace of a new key follows from its area. `node scripts/i18n.cjs namespaces` lists them:

| Namespace | Areas (key prefixes) |
| --- | --- |
| `app` | `brand`, `header`, `layout`, `window`, `status`, `welcome`, `toast`, `loading`, `drop`, `fileInput` |
| `board` | `board`, `search`, `list`, `panel`, `canvas`, `measure`, `tool`, `inspector` |
| `common` | `common`, `unit`, `side` |
| `dialogs` | `help`, `recents`, `info` |
| `diagnostic` | `diagnostic` (the format diagnostic report dialog) |
| `formats` | `parse` |
| `kinds` | `kind` |
| `native` | `native` (main-process dialogs and errors) |
| `network` | `network`, `update` |
| `notes` | `notes` |
| `settings` | `settings` |
| `support` | `support` |
| `documents`, `pdf`, `schematic`, `workspace` | empty for now: they receive the texts of the Phase 1 workspace, which still has English-only tables marked `// i18n: pending` |

A value is a text, or a plural object (`{ "one": "{count} pin", "other": "{count} pins" }`) chosen with the CLDR rules of the language from `params.count`. Placeholders are `{name}`. Keys never contain the English wording, so improving a text never renames a key.

## How they are loaded

- Main process: `electron/i18n.cjs` calls `loadCatalog(language)` of `electron/locale-catalogs.cjs`, which merges the `.json` files of the language folder in file-name order. The directory listing is the registry. A key defined in two files throws.
- Renderer: `src/lib/i18n.ts` merges the same files at build time (`import.meta.glob`). English is imported by name in `src/lib/i18n-english.ts`, one line per namespace file; it types the keys (`MessageKey = keyof typeof en`) and is the runtime English catalog, so a key exists for the compiler exactly when `electron/locales/en/` has it. The other seven languages are not registered anywhere.
- Packaging: `electron/**/*` already selects every file below `electron/locales/`; `tests/portable-config-checks.cjs` checks that each namespace file of each language is selected for the Windows build, and the macOS and Linux files carry the same patterns.

## Adding a key

Add it to all eight languages at once, in the right namespace:

```
node scripts/i18n.cjs add notes.exportDone --values new-texts.json
node scripts/i18n.cjs add support.thanks2 --en "Thank you" --hu "Köszönjük" --de "Danke" --fr "Merci" --it "Grazie" --sk "Ďakujeme" --pl "Dziękujemy" --uk "Дякуємо"
```

`new-texts.json` is `{ "en": "...", "hu": "...", "de": "...", "fr": "...", "it": "...", "sk": "...", "pl": "...", "uk": "..." }`; a plural value is an object (`"en": { "one": "{count} pin", "other": "{count} pins" }`), also on the command line as JSON. The script refuses a missing language, different placeholders, missing plural forms of a language (Slovak needs `few`, Polish and Ukrainian `few` and `many`), padded or decomposed text and a key that exists, and writes nothing then. It inserts the key after the last key of the same area, so branches that add keys of different areas do not touch the same lines. Without `--namespace` the namespace is the one that holds the area already, else the one named like the area. A new feature gets a new namespace: `--namespace report --create-namespace` creates the eight files; then import `en/report.json` and spread it in `src/lib/i18n-english.ts` (the layout test names the missing line).

Texts that are English-only today and marked `// i18n: pending` are translated into catalog keys the same way; lower the matching numbers in `src/lib/i18n-lint.test.ts` as you go.

## Keys written in the old flat layout

A branch that was started before the namespaces and added keys to `electron/locales/<language>.json` is moved over with its flat files and the flat files of the merge base, so that only what the branch changed is taken (a text that only the repository changed is left alone):

```
mkdir flat base
for l in hu en de fr it sk pl uk; do
  git show <branch>:electron/locales/$l.json > flat/$l.json
  git show $(git merge-base <branch> HEAD):electron/locales/$l.json > base/$l.json
done
node scripts/i18n.cjs import-flat flat --base base --dry-run
node scripts/i18n.cjs import-flat flat --base base --apply-changes
```

Keys the branch added are added to the namespaces (all eight languages are required); texts it changed are listed and replaced with `--apply-changes`; a text changed on both sides is reported as a conflict and left alone; keys the branch removed are listed, not removed. The merge itself reports the eight flat files as modified on one side and deleted on the other: resolve it by deleting them. Without `--base` every key of the folder counts and any differing text is reported.

## Checks

- `src/lib/i18n.test.ts`: key, placeholder and plural parity, leftovers of other languages, alphabets, fixed tokens, native/web parity, fallback behaviour.
- `src/lib/i18n-layout.test.ts`: the folder and file layout, one namespace per key and per area, the same namespace of a key in every language, English as the reference of every language (exact key set, placeholders, plural structure), the registry of `i18n-english.ts`, the native loader.
- `src/lib/i18n-lint.test.ts` (scanner: `scripts/i18n-lint.mjs`): no user-visible English literal in `src/components/**` (JSX text, `title`, `aria-label`, `placeholder`, strings that read like interface text) and no `i18n: pending` marker outside the allow-lists in that test. The lists are exact per file, so they only go down; `node scripts/i18n-lint.mjs --verbose` prints every finding. Brand names, units, key names, class names, catalog keys, comparisons and developer errors are not findings.
- `src/lib/i18n-script.test.ts`: the add and import commands, on a copy of the catalogs.

## Adding a language

Create `electron/locales/<language>/` with every namespace file, then register the code in `LANGUAGES`, `LANGUAGE_NAMES`, `LOCALE_TAGS` and the `merged` object of `mergeCatalogs` in `src/lib/i18n.ts`, in `LANGUAGES` and `LOCALE_TAGS` of `electron/i18n.cjs`, in `LANGUAGES` and `LOCALE_TAGS` of `scripts/i18n.cjs`, and in the README language table.
