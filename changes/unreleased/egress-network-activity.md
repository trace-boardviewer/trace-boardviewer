- Network layer: every network request of the main process now goes through one module, `electron/net/egress.cjs`. A feature registers there with an exact https host list (optionally exact paths or path prefixes), GET/HEAD only, a response size cap, a time cap, fixed headers (a fixed `Accept-Language: en` and `User-Agent: TRACE-Boardviewer/<version>`, never a cookie, an authorization or a referrer), redirects refused (also when a response reports a redirect, a 3xx status or another URL), a limit of requests in flight and an optional opt-in setting that is read from main-process state at the moment of each request. Requests run on an in-memory Electron partition (`trace-egress`) with no cache, no permissions and no downloads, whose request filter cancels any URL that no feature may reach. A static check fails if any other main-process file calls `net.fetch`, `fetch`, `http(s)`, a WebSocket or similar; the renderer CSP stays `connect-src 'self'` and is pinned by a test.
- The update check is the first feature on the layer, with unchanged behaviour: the same single GET to the releases API, the same four request headers, 8 s and 256 KiB limits, strict tag validation and the same rate-limit handling (403/429, `Retry-After`, `X-RateLimit-Reset`, never less than a minute or more than an hour). The `updateCheck` setting stays on by default; the start-up check is skipped by the renderer when it is off, and Check now (a user action) works with it off, as before.
- Network activity log: every request and its outcome (time, feature, host, path without query, status, bytes, duration, and an error class from a fixed list, never an error message, header or body) goes into a bounded in-memory ring log (200 entries by default, at most 1000), including requests that policy refused before sending and requests still running. The renderer can read it and empty it through two new trusted-sender IPC channels (`trace:get-network-activity`, `trace:clear-network-activity`, exposed as `getNetworkActivity` and `clearNetworkActivity`, neither reads an argument); it can neither start a request nor name a URL, a host or a feature.
- Settings > Network: a new section lists the network features with their state in words (On or Off) and the hosts each may contact, and a Network activity view shows the log (time, feature, host and path, result, newest first) with Refresh and Clear list. It refreshes every two seconds while it is open, works with the keyboard (native buttons, a focusable scrolling region, a polite status line) and is hidden when the preload lacks the two calls. All new text is in all eight languages.
- Audited download function (`download()` of the layer): writes only into a folder chosen by the main process, names the file by the SHA-256 of its bytes and one extension fixed by the feature (nothing from the URL or the server reaches the file system), writes to an exclusive private temporary file, caps the size, can verify an expected digest, returns the path and the digest and removes the temporary file on every failure. No feature uses it yet.
- Tests: the egress policy with injected fetches (registration, host/scheme/port/credential/query/path/method allow-list, tricky and un-normalized URLs, request shape, redirects, size, slow, endless and stalled bodies, caller limits that can only tighten, opt-in and its user-action bypass, log content and bound, in-flight limit, download), the production transport, the static isolation scan and the CSP pin, the main-process integration (forged senders and subframes, ignored arguments, lazily created partition, logged outcomes of the update check), and vitest for the report checks, the result labels, the markup in all eight languages and the Settings dialog with and without the bridge.
- Docs: README and SECURITY describe the single network module and the Network settings.
