- Notes now stay on the part and pin they were written for, even when a later version reads the board file differently. A note used to be tied to the position of its part in the reader's output, so a reader fix that dropped or reordered one component could silently move every later note to another part. Notes are now saved under the reference and the pin number from the board file (all pads that share a pin number are one pin). Opening a board converts its existing notes once; the first save that replaces them keeps the old notes file beside the new one as `<board key>.json.positional.bak`.
- Where the board file does not name a part or pin uniquely (several parts with the same reference, a part without a reference, a pad without a number), the note is tied to its position on the board and the inspector and the note editor say so; a part or pin that cannot be told apart from another one even by position gets no note and the reason is shown.
- Notes that cannot be matched to a part of the open board, for example because a later reader no longer has that part, are never dropped: a count appears in the status bar and the new **Unresolved notes** list shows each note's text, measurements and what it was attached to, with Copy and Delete. A note is deleted only when you delete it. New texts are in all eight languages.
