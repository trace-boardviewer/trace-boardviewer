- Format diagnostic report: **Help, Format diagnostic report...** describes a board file that does not open or opens wrongly without revealing anything of it. You choose the file (any file, also one TRACE does not recognise), TRACE analyses it on your computer, shows the report and a plain-language list of what it contains, and you save it to a place you choose. The report holds counts, sizes and format facts only: which readers recognised the file and how sure each was, the step and a short error code where a reader stopped, how often the format's own keywords occur, the order of magnitude of the numbers, the rounded counts of parts, pins and nets, and plausibility checks that show whether units, pad angles or the bottom side were read wrongly. It never holds the file name or folder, any text of the file, coordinates, raw bytes or keys. Nothing is uploaded and the clipboard is touched only by the Copy text button.
- Two opt-in switches, both off by default: level 2 (the collapsed shape of the first lines of each section and the tag and length of the first binary blocks) and a repeat-detection code (an HMAC under a random secret that stays on your computer, never an unsalted hash). A remaining-risk notice is shown with the report.
- A new GitHub issue form, "Format request or file that does not open", takes the report text and asks you to confirm that you did not attach the board file.
- For developers: an optional `structure` hook on board adapters (`docs/ADAPTERS.md`, section 10) describes a format's layout through a sink that accepts only whitelisted facts; adapters without one are reported with detection and result facts only. The report schema `trace-format-diagnostic/1` is closed and pinned by a golden file; canary and property tests prove that no seeded reference, net, value, coordinate or key reaches a report in any encoding. See `docs/DIAGNOSTIC-REPORT.md`.
- All new texts are in all eight languages.
